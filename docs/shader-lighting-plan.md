# 方案 C：彩色动态光照（苍/赫/茈 像火把一样照亮 + 真实阴影）

> 状态：**方案已确定，尚未实现**（本文件是落地清单，按顺序做即可）。

## 为什么必须走光影

Minecraft 1.20.1 的光照引擎只有**方块光（白色、0~15 级）**，没有颜色、没有动态点光源。
"彩色 + 照亮周围 + 真实阴影" 三者同时成立，只能由**光影包（shader pack）在延迟渲染里读自发光/自定义 buffer** 实现。

## 前置（用户要求"内置一个开启的光影前置"）

1. **着色器加载器**：`Oculus`（Forge 1.20.1 的 Iris 移植）。
   - 不能把它的 jar 塞进本模组 jar（违反发布规范、也会被依赖校验拒绝）。
   - 落地方式：①`META-INF/mods.toml` 里声明 **optional dependency `oculus`**；②随整合包/发布页**附带下载链接**；③首次启动检测到缺失时在聊天栏提示安装（不阻断游戏）。
2. **光影包**：随模组发布一个精简 pack（zip），用户在 `shaderpacks/` 启用。
   - 说明文档里给出启用步骤；模组本身不写 `shaderpacks/` 目录（避免越权）。

## 光影里要加的三件事

1. **自发光点光源**：在 shader 里为 苍 / 赫 / 茈 各注册一个**点光源**，参数 = 位置 + 半径 + 颜色 + 强度。
   - 颜色：苍 `#5AA8FF`、赫 `#FF5B3A`、茈 `#B062FF`。
   - 位置/半径来源：模组每刻把光球信息写进一个**自定义 buffer 或 uniform 数组**（例如最多 8 个光源的 `vec4 posRadius[8]` + `vec4 color[8]`）。
2. **延迟光照累加**：在 deferred 阶段把每个光源按 `1/d²` 衰减累加到场景光照上（带阴影：用 shadow map 或屏幕空间射线）。
3. **体积光（可选）**：沿视线对光源做若干步采样累加——这一步才是真正的"体积雾"，之前用加法层做的是假的。

## 模组侧要改的地方

| 位置 | 改动 |
|---|---|
| `GojoFx`（BLUE/RED/PURPLE 分支） | 每刻把光球 `{pos, size, color, strength}` 写进一个静态光源表 |
| 新增 `GojoLightUniforms` | 维护最多 8 个活动光源，供渲染层读取并传给 shader（uniform 或 buffer） |
| 渲染层 | 需要与 Oculus 的 uniform 接口对接（Iris 的 `IrisApi` 暴露了自定义 uniform/buffer 注入点） |
| `mods.toml` | 加 optional dependency `oculus`；缺失时聊天栏提示 |
| 发布物 | `dist/` 里附一个精简 shader pack（zip）与使用说明 |

## 验收标准

- 关闭光影时：现有顶点通路/加法表现不变，游戏不崩、不报缺失。
- 开启光影时：苍/赫/茈 会**真的照亮**周围方块与生物，颜色正确、被遮挡处变暗（有阴影）、移动时照亮范围跟着移动。

## 预估工作量

- shader pack（含彩色点光 + 阴影 + 可选体积光）：半天到一天（要反复看画面调）。
- 模组侧 uniform 注入 + 缺失降级：2~3 小时。
- 主要风险：Oculus 的 uniform 注入接口版本差异；建议先做**一个颜色、一个光源**跑通，再扩到三色多光源。
